# Vispeak — План разработки

> Обновляется каждым этапом. КОММИТИТСЯ в репозиторий (НЕ в .gitignore) —
> синхронизация между машинами. Прошлый рассинхрон случился из-за игнора.
> Язык: русский (проза и решения), технические идентификаторы/код/пути/лог-метки —
> в оригинале (англ.).

Vispeak — desktop-приложение для локальной офлайн-транскрибации
голоса по глобальной горячей клавише (аналог SuperWhisper). Windows + Linux (порт для Fedora, Arch, Ubuntu и Debian).
Разработка ведётся промтами через агента (Antigravity IDE). Проект начат с нуля.

---

## Стек технологий
- **Backend**: Tauri 2 + Rust
- **Frontend**: React + TypeScript + Tailwind CSS (v4), npm
- **Аудио**: `cpal` (запись), `rubato` -> кастомный ресемплер для 16 kHz
- **VAD**: Silero VAD (ONNX, 2.2 МБ, встроена в бинарник)
- **Движки транскрибации** (trait TranscriptionEngine): `whisper-rs` (Whisper cpp,
  GGML) + `transcribe-rs` (ONNX: Parakeet, GigaAM, Canary) + `transcribe.cpp`
  (ggml: Nemotron, Qwen — статус имплементации уточняется)
- **Симуляция ввода**: Windows `enigo`; Linux X11 `xdotool`/`xclip`, Wayland `ashpd` RemoteDesktop + `wl-clipboard`
- **Хоткеи**: `rdev` (низкоуровневый системный хук WH_KEYBOARD_LL, левые/правые
  модификаторы, одиночные модификаторы)
- **Прочее**: rusqlite (история), rodio (звуковые сигналы), Windows CoreAudio /
  WASAPI (ducking); Linux `pactl` / PulseAudio / PipeWire-Pulse

## Инварианты (нарушать нельзя)
- Оверлей НИКОГДА не берёт фокус ввода (`focus: false`, проверка Блокнотом).
- Аудио строго mono 16кГц; транскрибация в отдельном потоке (не блокирует UI).
- Хоткей работает при свёрнутом окне.
- duck/restore строго парные (guard / Drop-семантика).
- Дизайн только через семантические токены (никаких хардкод-цветов).
- Все строки UI через i18n (ru/en); из Rust — коды ошибок, не тексты.
- Новые поля настроек — только с `#[serde(default)]` (обратная совместимость).
- Позиционирование окон — в физических пикселях с учётом scale_factor монитора.

## Архитектура (цикл диктовки)
1. **Глобальный хоткей**: слушаем клавиатуру через `rdev` в отдельном потоке.
   Режимы Push-to-Talk и Toggle, различение левых/правых модификаторов. Дефолт —
   Ctrl+Space. PTT <300мс удержания — тихая отмена; toggle-запись <0.5с ->
   «речь не распознана». Esc — глобальная отмена (регистрируется на время цикла).
2. **Запись**: через `cpal` старт записи с микрофона. Программное усиление (Gain)
   с клиппингом (защита от перегруза). Показ оверлея («Запись...»).
3. **Обработка**: по отпусканию хоткея аудио -> Silero VAD (обрезка тишины по
   краям) -> whisper-rs / transcribe-rs. Модель загружена в память заранее,
   транскрибация в отдельном потоке.
4. **Вставка** (порядок СТРОГО зафиксирован):
   `запись текста в буфер` (для копирования/вставки или при policy=keep)
   -> симуляция `Ctrl+V` (enigo)
   -> пауза на обработку вставки (50 мс)
   -> `finalize_clipboard(policy)` (restore: восстановление старого буфера ~300мс;
      keep: верификация с повторными попытками)
   -> автоотправка Enter (`Key::Return` / `Ctrl+Return`) строго ПОСЛЕДНЕЙ.
   Оверлей скрывается.

## Оверлей (3 скина)
Переключается настройкой `overlay_skin` ("full" | "compact" | "mini"). Все скины
используют общий хук `useOverlayState`. При смене настройки размер и положение окна
пересчитываются в `src-tauri/src/lib.rs` перед показом.

- **Полный (`OverlayFull`)**: ~400x160 px. Шапка (целевое приложение), текстовые
  подсказки, иконка приложения, эквалайзер, «Esc — отмена». Свечение состояний:
  запись #ff5533, обработка cyan, успех зелёный (+превью), ошибка красный.
- **Компактный (`OverlayCompact`)**: ~340x90 px. Капсула в одну строку с
  укороченной волной, без шапки. Обработка — три пульсирующие точки + «Обработка...»;
  успех — галочка (~700мс); ошибка — крестик+текст; «Скопировано» в режиме «только
  копировать».
- **Мини (`OverlayMini`)**: ~96x34 px (~144x82 логическое окно с учётом glow).
  Капсула-пилюля «У курсора» строчной высоты: запись — эквалайзер на всю ширину
  (12 точек высотой до 22 px, ультратонкие полоски 1.5 px с просторным зазором 4 px и шагом 5.5 px); обработка — три пульсирующие точки (1.5 px); успех — галочка
  (~16 px, ~600 мс); ошибка — крестик (~16 px).

**Осознанное решение (тема оверлея)**: все скины индикатора следуют выбранной
теме приложения (Системная/Тёмная/Светлая). Цвета состояний (красный/cyan/зелёный) — часть языка продукта и сохраняются в любой теме.

### Положение оверлея
Зависит от скина и настройки `overlay_position`.
1. **"full" и "compact" (или при сбое определения курсора)**: универсальная
   якорная модель относительно `rcWork` целевого монитора (Низ по центру / Правый
   нижний угол / Левый нижний угол / Верх по центру).
2. **"mini" ("У курсора")**: в `start_recording` вызывается
   `caret_position::get_caret_position` с таймаутом 100 мс: координаты каретки через
   `IUIAutomation` (сначала `TextPattern2.GetCaretRange`, затем
   `TextPattern.GetSelection`), при неудаче фоллбек на `GetGUIThreadInfo`
   (`rcCaret`).
3. **Валидация и физические координаты**: любые координаты проходят
   `validate_caret_rect`: разумные размеры (`0 < height <= 3000 px`,
   `0 <= width <= 5000`), внутри экрана монитора (`MonitorFromRect`), внутри
   видимого окна приложения `GetWindowRect(target_hwnd)` с допуском `±64 px` на
   тени/рамки. Позиционирование — `tauri::Position::Physical(PhysicalPosition)` с
   точным учётом `scale_factor` каждого монитора.
4. **Классификация `CaretKind` и единое правило**:
   - **`Caret`**: узкий прямоугольник (`width <= 4` ИЛИ `height <= 40 && width <=
     height * 2`).
   - **`Field`**: небольшой ввод (`width <= 600 px` И `height <= 60 px`) — поиск,
     адресная строка, чат.
   - **`Area`**: больше (`width > 600 px` ИЛИ `height > 60 px`) — многострочные
     редакторы (VS Code, Monaco, большие `textarea`).
   - **Горизонталь (X)**: точка привязки — левый край прямоугольника (`rect.left`)
     для всех типов; капсула ЦЕНТРИРУЕТСЯ на этой точке; затем горизонтальный кламп
     к `rcWork` с отступом 8 px.
   - **Вертикаль (Y) — ВСЕГДА НАД**: низ видимого края капсулы на 8 px выше верха
     прямоугольника. Исключение: если верх капсулы выходит за `rcWork.top` — капсула
     ПОД (верх капсулы на 8 px ниже низа прямоугольника).
   - **`Area` + мышь**: если курсор мыши ВНУТРИ прямоугольника Area, `pt.y` мыши
     используется только для ВЕРТИКАЛИ (капсула над нужной строкой); по горизонтали
     — общее правило (левый край). Мышь вне Area — чистый фоллбек на якорь
     (`anchor_fallback`).
   - **`GLOW_PADDING`**: все отступы (8 px) от ВИДИМОГО края капсулы с компенсацией
     прозрачного поля свечения (`phys_glow`).

### Тестовая матрица позиционирования "У курсора" (~96x34 px)
| Контекст | Метод | CaretKind | above/below | Поведение |
|---|---|---|---|---|
| Блокнот, центр текста | Win32/UIA | caret | above | центр по X, ровно 8 px НАД кареткой |
| Блокнот, первая строка у верха окна | Win32/UIA | caret | below | упор в `rcWork.top` -> ПОД кареткой |

## Дизайн-система
- Near-black минимализм (референсы: оверлей в стиле Spokenly, настройки в стиле
  Raycast): фон #0d0d0d, поверхности #1c1c1e, границы #2a2a2e, текст
  #f5f5f7/#8e8e93, акцент #ff5533, успех #7ed491, обработка #4dd8e6. Радиусы
  12-16px, чипы pill, без glassmorphism/blur/градиентов.
- Фирменный мотив — точечная волна (эквалайзер из точек).
- Главное окно 900x600: сайдбар ~220px (Модель / Управление / История / Общее /
  О приложении) + контент; статус «Готов» + чип хоткея.
- Темы (Системная/Тёмная/Светлая) — семантические CSS-переменные (`--color-window`,
  `--color-surface`, `--color-border`, `--shadow-accent-md`), переключение в
  реальном времени с автоопределением `prefers-color-scheme`. Оверлей также
  меняет тему синхронно с главным окном.

## Design decisions & history (почему так, что отвергнуто)
- Оверлей: glassmorphism -> near-black минимализм (сознательный разворот).
- Тема оверлея изначально была только тёмной, затем отвязана и теперь
  синхронизируется с темой приложения.
- Мини-скин: горизонталь центрируется на левом крае строки, вертикаль всегда над —
  выбрано после ~6 итераций других вариантов.
- История: остановились на off/5/10 вместо раздельных политик аудио/текст.
- Буфер: «Убирать после вставки» невозможно сделать «вообще не писать в буфер» для
  clipboard-способов (Ctrl+V читает из буфера); след в истории Windows (Win+V) —
  принятое ограничение. Не пишущий в буфер способ — только посимвольный enigo.
- Референсы дизайна выбирались по сгенерированным изображениям и скринам реальных
  приложений (Spokenly, Raycast).
- Иконка: убрана квадратная подложка и внешнее свечение, осталось только облако.
- Эквалайзер оверлея: убрана искусственная зеркальная купольная огибающая ("горка"); переведено на 60 FPS rAF с асимметричным сглаживанием (fast attack / slow decay) и фазовыми сдвигами полос.
- Оверлей: убран оранжевый контур (stroke), оставлено только мягкое свечение. Реализованы полностью идентичные плавные fade-in / fade-out анимации.
- Акцентный цвет: реализован выбор из 3 вариантов (Оранжевый/дефолт, Белый, Чёрный) в разделе «Общее» (настройка `accent_color`). Акцент применяется мгновенно через атрибут `data-accent` без перезапуска приложения и влияет только на бренд-акценты в меню настроек и состояние «Запись» у оверлея (свечение + эквалайзер). Состояния оверлея «Обработка» (`--color-processing`), «Успех» (`--color-success`) и «Ошибка» (`--color-error`) изолированы от акцентного цвета. Добавлены реактивные предупреждения при выборе рискованных комбинаций (Чёрный на тёмной теме, Белый на светлой теме). Все текстовые подписи карточек и выборов интерфейса («Системная», «Тёмная», «Светлая», «Оранжевый», «Белый», «Чёрный», «Полный», «Компактный», «Мини», бейджи и кнопки записи хоткея) по всему приложению используют статический токен `--primary` (`text-primary`), гарантируя 100% читаемость на светлой и тёмной темах без риска слияния с фоном при белом или чёрном акцентном цвете. Превью карточек акцентного цвета выполнены в виде мини-макетов капсулы оверлея без жестких рамок с соответствующим мягким радиальным свечением (`shadow-[0_0_16px_...]`), в точности повторяющих визуал боевой капсулы.

## Bug Fixes & Stability (история решённых багов)

### Смена горячей клавиши не применялась + одиночный модификатор как хоткей (`ControlsPage.tsx`)
- **Stale closure в `handleKeyUp`**: `saveSettings` читал `inputHotkey` из замыкания предыдущего рендера — к моменту `keyup` React state ещё не обновился. Решено: добавлены `useRef` (`inputHotkeyRef`, `inputCancelHotkeyRef`), обновляемые синхронно в `handleKeyDown`, `onFocus`, `onBlur`; `handleKeyUp` читает из `.current`.
- **Двойная запись модификатора**: при нажатии `ControlRight` старый код добавлял и `"Control"` (из `e.ctrlKey`), и `"ControlRight"` → `"Control+ControlRight"`. Решено: если нажатая клавиша — сам модификатор, пропускаем `e.ctrlKey/altKey/shiftKey` и добавляем только конкретный вариант (`"ControlRight"`).

### Капсула оверлея отображается прямоугольником/квадратом на Linux (`App.css`, `OverlayWindow.tsx`)
- **Первопричина**: В Tailwind v4 токен `rounded-full` по умолчанию использует `calc(infinity * 1px)`. При сборке (LightningCSS/Vite) это значение компилируется в `border-radius: 3.40282e38px` (максимальное 32-битное число с плавающей точкой `FLT_MAX`). Движок WebKitGTK при расчёте скругления углов (`FloatRoundedRect` в float32) суммирует радиусы смежных углов: сложение двух `FLT_MAX` переполняется в `+Infinity`, коэффициент масштабирования радиуса `width / Infinity` становится `0.0`, а итоговый радиус — `0.0` (или `NaN`). В итоге движок отключает скругление и рисует обычный прямоугольник с прямыми углами.
- **Решение**: В `@theme` в `src/App.css` явно переопределён `--radius-full: 9999px`. При `9999px` алгоритм масштабирования углов работает штатно и оверлей сохраняет форму капсулы (pill) во всех состояниях (запись, обработка, результат). Также явно задан `background: transparent !important` для `html, body, #root`, и убран `backdrop-blur-md`.

### Настройки: читаемость карточек «Вид индикатора» при светлой теме
При использовании светлой темы и чёрного акцентного цвета карточки предпросмотра оверлея сливались с фоном или теряли рамку выделения. Решено: карточки приведены к единообразному виду (`h-[52px]`); невыбранные получили явный `border-neutral-200` + лёгкую тень (`shadow-sm`); контейнеры превью всегда тёмные (как реальный оверлей), а цвет меняет только тонкая полоска внутри (как индикатор `bg-accent`).

### Звуковой сигнал: слишком громкий старт и звонкость
Сигналы старта и ошибки были слишком громкими и резкими. Решено: старые звуки заменены на чистый сгенерированный sine wave (500Hz/400Hz, 1ms attack) через rodio. Амплитуда снижена до `0.5`, и формула `decay_k` скорректирована для затухания.

### Прямоугольная обрезка свечения на пике пульсации оверлея (`App.css`, `OverlayWindow.tsx`)
Причина: на пике анимации `@keyframes glow-pulse-accent` (50%) размытие тени `box-shadow` достигало `32px`, в то время как прозрачный отступ вебвью-окна вокруг капсулы (`GLOW_PADDING`) в Rust равен `24px`. В результате на пике пульсации тень физически обрезалась прямоугольным краем окна. Решено: ограничение пикового blur radius до `20px` (`0 0 20px var(--glow-max)`), что оставляет 4px запас полного затухания в прозрачность до границ окна без изменения размеров окон и логики позиционирования.

### Caret-позиционирование в Electron (VS Code, Slack, Antigravity)
Обход UIA-бага с огромными зонами (degenerate text selection): отказ от
`ExpandToEnclosingUnit(TextUnit_Character)`; валидация габаритов
(`FIELD_MAX_WIDTH = 4000`, классификация Field); приоритет точного bounding rect;
фикс anomaly detection в lib.rs (кламп X без ложных аномалий). Улучшено логирование
`caret_trace`, чистка неиспользуемых переменных/импортов в caret_position.rs и lib.rs.

### Сбой позиционирования "У курсора" (отрицательный top / дрифт при DPI > 100%)
Причина: некорректный `hwndFocus` при нулевом `hwndCaret` в `GetGUIThreadInfo` +
передача физических координат в логический `set_position(Position::Logical)`, где
Tauri повторно умножал на scale_factor. Решено: строгая валидация
`validate_caret_rect` (высота, `rcMonitor`, `GetWindowRect`) + переход на
`Position::Physical(PhysicalPosition)` с учётом scale_factor монитора.

### Фризы ввода ("slideshow mouse")
Устранена утечка зомби-rdev-потоков; heartbeat обновляется на ВСЕ события (включая
мышь); callback хука переведён в lock-free минимум с делегированием обработки
(`prune_stuck_keys`, валидация хоткея) в фоновый воркер.

### Защита хоткея от скриншотеров/перехватчиков (`hotkeys::setup_hotkeys`)
Сторонние скриншотеры (Snipping Tool `Win+Shift+S`, ShareX, Lightshot `Alt+S`)
ломают хук `WH_KEYBOARD_LL` (`rdev::listen`) двумя способами:
- **Case B — залипание клавиш**: скриншотер перехватывает KeyRelease обычной
  клавиши/модификатора. Решено: `is_key_physically_pressed` расширена на ВСЕ клавиши
  (`VK_A..VK_Z`, `0..9`, `F1..F12`, `VK_BACK/RETURN/TAB`, модификаторы) через
  `GetAsyncKeyState` в `prune_stuck_keys()` (перед каждым событием и по таймеру раз
  в 2.5 с, лог `[debug][hotkeys] Self-correcting stuck key: ...`). Защита в глубину:
  `is_hotkey_pressed` требует все клавиши хоткея и отсутствие посторонних
  модификаторов, но игнорирует посторонние обычные клавиши (залипшая S не блокирует
  Right Ctrl; Ctrl+Shift+X не срабатывает от хоткея Ctrl+X).
- **Case A — снятие хука системой**: при блокировке очереди сообщений Windows молча
  отключает хук. Решено Watchdog-таймером: при тишине хука (`heartbeat > 5s`) и
  активном вводе (`GetLastInputInfo`) выдерживается пауза 600 мс (защита от ложных
  перезапусков при выходе из простоя); если событий от rdev так и нет — инкремент
  `LISTENER_GEN` и перезапуск `rdev::listen` в новом чистом потоке (generation guard:
  устаревший listener становится пустышкой). Debug-лог зажат (обычные клавиши не
  логируются — приватность).

### Буфер обмена — самотесты и инварианты (`finalize_clipboard`, `paste.rs`)
Повторная запись распознанного текста (re-check) разрешена СТРОГО внутри ветки
`policy == "keep"`. Ветка `restore` выполняет только восстановление `previous_text`
(до 15 попыток за 450 мс, защита от блокировки буфера целевым окном после Ctrl+V).
Был маятниковый баг keep<->restore, лечили дважды. Любые правки в paste.rs
верифицируются интеграционными самотестами `cargo test --lib paste::tests`
(проверка через 1.5 с на реальном системном буфере, синхронизация через
`CLIPBOARD_MUTEX`).

### Аудио: зомби-стримы, ducking, watchdog (`audio::run_audio_session`, `ducking`)
- **Зомби-стрим и мёртвый ресемплер**: счётчик сырых сэмплов рос в фоне вне записи,
  ресемплер выдавал 0 накопленных. Причина: гонка потоков в
  `start_recording`/`start_preview`. Решено: атомарная остановка предыдущего канала
  (`stop_tx.take().send(())`) и установка флагов (`is_recording`, `stop_tx`) строго
  внутри единого Mutex-лока до запуска нового потока; 100% изоляция состояния
  (`NearestResampler` и буфер сбора создаются локально в каждом короткоживущем
  `worker_process`). Если сэмплов 0 или разрыв >500 мс — Watchdog.
- **Ducking: двойное снижение и восстановление после сбоя** (`DuckingGuard`,
  `ducked_volumes.json`): при перекрывающихся циклах громкость сторонних приложений
  (VLC) снижалась повторно и оставалась приглушённой. Решено: флаг-гард `IS_DUCKED`
  против повторного приглушения; снимок исходных уровней `ORIGINAL_VOLUMES` держится
  в памяти И синхронно сохраняется в `%APPDATA%/Vispeak/ducked_volumes.json`. При
  старте (`restore_all_on_startup` в lib.rs) и при завершении/сбое
  (`DuckingGuard::drop`) все сессии возвращаются к исходному уровню, файл снимка
  удаляется.
- **Ложное срабатывание Watchdog в тишине**: агрессивное шумоподавление микрофонов
  (или Windows Voice Isolation) останавливало аудиопоток в условиях полной тишины.
  Watchdog прерывал запись с ошибкой `"err_mic_not_found"` через 500мс тишины.
  Решено: удален gap watchdog для тишины внутри сессии, начальный таймаут увеличен до 1500мс.
- **Громкость звукового сигнала (cue)** (`audio::play_cue`): пиковая амплитуда envelope снижена с 0.5 до 0.2 для более комфортного восприятия.

Точки обработки (`processing-dot`) уменьшены до 1.5px с увеличенным интервалом. Число полосок динамически адаптировано во всех скинах (Full: 49, Compact: ~25, Mini: 12), обеспечив идеальную читаемость каждого элемента без изменения геометрии и размеров самих скинов.
- **Внедрение настройки «Стиль эквалайзера» (4 варианта визуала)**:

  3. *Нити-неон* (`neon_threads`): две шелковистые волновые линии (яркая и полупрозрачная), переплетающиеся между собой со световым шлейфом (комета).
  4. *Частицы* (`particles`): мягкий гидродинамический «гелевый» рой частиц по всей площади капсулы с плавным расширением и свечением на голосе без резких скачков.

### Известные проблемы (Troubleshooting)

- **Оверлей "зависает на галочке" при моментальном старте новой диктовки в Toggle-режиме**: Если пользователь начинал новую диктовку в пределах 300мс после завершения предыдущей (пока шёл процесс вставки текста `paste_text`), новая диктовка успешно начиналась, но затем событие `transcription-done` от старой диктовки перетирало UI-состояние. В итоге оверлей показывал зеленую галочку, устанавливал таймаут 1.5с на скрытие, а затем Rust игнорировал команду `hide_overlay`, так как `state.is_recording` уже был `true` от новой диктовки. Решено: В `transcribe.rs` перед отправкой `transcription-done` проверяем `state.is_recording`; если началась новая диктовка — пропускаем отправку устаревшего события.

- **whisper-rs-sys / bindgen на Windows** не находит `stdbool.h`, `stdio.h`
  (ошибки `size_of::<_G_fpos_t>() - 16usize`): добавить в `.cargo/config.toml` пути
  к заголовкам LLVM и MSVC:
  ```toml
  [env]
  BINDGEN_EXTRA_CLANG_ARGS = "-I\"C:/Program Files/LLVM/lib/clang/22/include\" -I\"C:/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/VC/Tools/MSVC/14.44.35207/include\" -I\"C:/Program Files (x86)/Windows Kits/10/Include/10.0.26100.0/ucrt\" -I\"C:/Program Files (x86)/Windows Kits/10/Include/10.0.26100.0/shared\" -I\"C:/Program Files (x86)/Windows Kits/10/Include/10.0.26100.0/um\""
  ```
- **onnxruntime DLL** в бандле: в dev работает — проверять установленную сборку
  отдельно (был кейс «в dev ок, установленное падает»).
- **Воспроизведение аудио из истории (Tauri 2 на Windows)**: для корректной работы `convertFileSrc(path)` и загрузки WAV-файлов из `%LOCALAPPDATA%` / `%APPDATA%` через `<audio>`, в `tauri.conf.json` в блоке `security -> assetProtocol` необходимо указать `scope`, включающий абсолютные пути Windows (`"$APPDATA/**"`, `"$LOCALAPPDATA/**"`, `"$APPLOCALDATA/**"`, `"C:/**"`, `"C:\\**"`), а в `Cargo.toml` у зависимости `tauri` должна быть включена фича `"protocol-asset"`. Кроме того, команда `get_history_audio_path` должна быть явно зарегистрирована в `tauri::generate_handler![...]` в `src-tauri/src/lib.rs` (иначе возникает ошибка `Command get_history_audio_path not found`, из-за которой воспроизведение прерывалось без звука).

### Linux troubleshooting

- Первичная проверка запуска выявила ошибку glob в Windows-путях `C:\**`. Linux-конфиг переопределяет asset scope на платформенные каталоги данных.
- Готовый ONNX Runtime (`ort-sys 2.0.0-rc.12`) требует glibc 2.38+: Ubuntu 22.04 не линкуется (`__isoc23_strtol/strtoll/strtoull`). Используем Ubuntu 24.04+ / Debian 13+; для старых систем нужен отдельно собранный runtime.
- В C++-движках по умолчанию включён `GGML_NATIVE`, который задаёт `-march=native`. Linux-пакеты собираются через `npm run build:linux` в отдельном `target/linux` (whisper-rs-sys не отслеживает GGML env для старого кеша): baseline x86_64 без фиксированных AVX/AVX2/FMA/F16C-флагов; Windows-сборка не меняется.
- `ashpd` remote_desktop также требует feature `screencast` при отключённых default features. Он включён для типов API; захват экрана не запрашивается.
- Первые проверки выполнялись во временном Ubuntu-контейнере. SELinux требует `--security-opt label=disable` для доступа к bind mounts этой проверочной среды. Стандартный запуск Vispeak не требует этого флага.
- Wayland требует соответствующих порталов в backend рабочего окружения; см. `docs/LINUX.md`. Потоковый ввод отключён из-за отсутствия идентификатора чужого активного окна. Нативное позиционирование/always-on-top зависит от композитора.
- Буфер восстановления сохраняет текст либо PNG, без полного набора форматов HTML/RTF. Текст после ошибки вставки остаётся в истории, если её хранение включено.
